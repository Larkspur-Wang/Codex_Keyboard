# 本地 Wi-Fi 协议合同

> 运行时真值以 `app/host/src/lan_voice.rs`、`app/host/src/lan_playback.rs`、
> `firmware/components/keyboard/src/codex_playback_wire.cpp` 和对应测试向量为准。

## 控制面

- 端口：Host UDP `17333`，可由受控环境变量覆盖测试端口。
- 设备和 Host 共享 32-byte device secret；秘密只在 Host 私有文件和固件 NVS。
- 所有 packet 携带固定 magic/version/type/长度和连接或请求 generation。
- 控制包使用截断 HMAC-SHA256；未知来源、旧 generation、重放、长度错误和认证失败均丢弃。

## 麦克风上行

- `EIHB`：发现/心跳。
- `EICC`：start/keepalive/stop 控制。
- `EIAU v3`：16 kHz mono PCM16 音频，携带 slot、session identity、sequence、timestamp 和 HMAC。
- `EIAE`：认证结束，冻结 last sequence。

到达时间不能替代采集时间轴。Host 只接受一个连续 session；缺帧、重复身份、空录音和超长录音
不能进入 ASR/FIFO。

## 总结下行

| 包 | 方向 | 语义 |
|---|---|---|
| `EIPR` | Device -> Host | 请求 slot 当前未读 generation |
| `EIPB` | Host -> Device | 宣布 exact generation、EIAD 长度/摘要和 transfer identity |
| `EIPD` | Host -> Device | offset 数据块；40-byte header 为 AAD，payload 为 AES-256-GCM |
| `EIPA` | Device -> Host | begin/data/cancel application ACK |
| `EIPF` | Device -> Host | I2S 实际排空后的完成证明 |
| `EIPK` | Host -> Device | heard/cache transaction 已提交，或 cancel 已确认 |

EIPD key 由 device secret、固定 context、完整 transfer identity 和 request nonce 派生；同一 transfer
中 nonce 由 offset 唯一决定。控制包保持 HMAC。Host 使用 stop-and-wait，下一个 offset 只有在 EIPA
确认后推进；最终 ACK 丢失时设备必须对完全相同的密文块重发 EIPA。

## 删除规则

`EIPB`、最后一个 `EIPD` 或网络发送成功都不能删除缓存。唯一消费路径是：

```text
matching EIPF
  -> Host verifies exact playback lease
  -> transaction marks generation heard
  -> cache reconcile deletes only unreferenced objects
  -> EIPK success
```

重复 EIPF 可重新触发幂等 cleanup/EIPK。PTT cancel、播放失败、超时、断线或错误 generation 均保留。

## 当前候选与发布差异

当前真机候选把完整 EIAD 有界下载到 PSRAM 后播放，以尽快验证真实扬声器和 deletion。最终发布版
要求有界 jitter/ring 边下边播；两者必须保持相同 lease、generation、finished 和 delete 语义。
